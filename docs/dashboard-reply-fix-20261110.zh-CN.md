# 长按A对齐后观测空字符串解析错误修复

2026-11-10，ACT_Train。

## 错误定位

现场13:56:23 BUTTON_A_LONG与ALIGN_START已出现，说明按钮与路径预检正常；13:56:24服务A的get_observations返回ValueError: could not convert string to float: ''。恢复查询继续失败。错误路径在DobotRobot.get_joint_state读取GetAngle并直接split花括号后map(float)，不是相机图像解析。

源码中Dashboard已有请求/回复互斥锁，但只调用一次recv(1024)，未按协议分号边界读取完整回复。TCP半包、粘包与延迟回复可能造成错位；空字段也可能是控制柜返回错误状态。本次旧异常没有保存原始回复，无法确定此次空字段属于哪一种。

## 修复范围

- 仅29999 Dashboard端口改用sendall及按分号完整收包，保留同次接收的后续帧。
- 使用原套接字超时作为完整帧的总接收期限；连接关闭、超时及超长回复明确报错，包含IP及原始部分数据。接收失败后禁用该流的后续事务，要求重连，避免继续错配迟到回复。不自动重发指令。
- GetAngle/GetPose严格验证指令回显、成功状态码、六个有限数值，错误包含机器人IP、查询名和raw回复。不补零、不使用旧观测顶替。
- 30003运动口原有发送及无回复超时行为保留；不修改运动参数、标定、归位、相机规格。

## 验证与生效

一轮tests/test_dashboard_reply.py、tests/test_teleop_regressions.py、tests/test_act_dataset.py：77 passed，15.21秒。覆盖拆包、合包、部分帧超时、断连、失败后不继续发送、运动端口兼容、错误状态/错指令/空值/NaN拒绝、角度单位及14维数据回归。既有API弃用警告保留。

未自动重启服务A或下发机器人动作。此修复必须在现场正常停跟随、退出B并按原手册关闭A/处理设备锁后，先A后B重启生效。A启动包含原有使能与夹爪初始化，按原操作手册清空夹爪活动范围。之后先单侧慢速对齐，再双侧空载录制验证。若控制柜仍返回错误，新日志将给出IP、状态和原始回复；本轮未复验真实长按A运动过程。

## 为什么单相机时没出现

1. 原三台共用USB 2.1集线器的并发数据量增加，导致相机超时；当前换集线器、改为USB 3.2直连后，两种流模式的重复启动与持续出图已通过。
2. 按钮过期已通过只读现场复现定位到首次HighGUI窗口创建：424ms窗口初始化导致313ms采样间隔，越过250ms门限。先创建窗口再启动主手后间隔降至32ms。三视角预览改变了同进程工作量与调度时序，使该启动缺陷暴露。
3. 本次单次recv和未经验证split的实现，在d473eec单相机基线中就已存在。当前证据不足以证明三相机直接造成控制柜空回复；它是独立的机器人通信处理缺陷。单相机运行中未遇到相同收包边界或控制柜回复条件，就不会显现同一异常。新代码处理的是这些边界条件，而非通过减少视角掩盖异常。
